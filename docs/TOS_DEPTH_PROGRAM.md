# TOS Depth Program

## Objective

Move the Terminal Operating Systems category from first-pass catalog coverage to specialist software-selection depth without changing TechSelectAI neutrality or ranking methodology.

The program expands TOS from **10 broad criteria to 85 buyer-selectable criteria**. The original 10 capability slugs remain for backward compatibility. Seventy-five new criteria are organized into nine terminal-operational modules:

1. Vessel & Berth Planning
2. Yard Strategy & Inventory
3. Gate, Truck & Landside Operations
4. Rail & Intermodal Operations
5. Equipment Dispatch & Automation
6. Reefer, DG & Special Cargo
7. Integration, Data & Ecosystem
8. Billing, Analytics & Operational Control
9. Platform Architecture, Resilience & Security

## Evidence rule

Taxonomy depth is not evidence depth. Every newly created granular criterion begins as `not_yet_verified` for each TOS product. A later vendor evidence pass may promote a criterion only when current first-party evidence supports the exact scope. Unknown is not unsupported.

Companion modules, optional products, project-specific integrations and implementation-dependent capabilities must remain partial or unknown unless the reviewed evidence establishes that they belong to the evaluated product/package.

## Progress

- Taxonomy foundation: migration 139 establishes 85 buyer-selectable criteria across nine operational modules.
- Kaleris N4 evidence pass: migration 140 reviews 31 granular criteria using current first-party Kaleris material. Optional optimization modules and project-specific integrations remain partial rather than being promoted as universal base-N4 features.

## Product follow-on

After evidence coverage is materially deeper:

- expose category-relative evidence depth on public product/comparison pages;
- build evidence-derived TOS comparison pages;
- add reusable TOS requirement templates for consultation intake;
- map selected criteria into RFP and business-case workflows;
- keep Fit Score driven only by buyer-selected requirements and the existing scoring methodology.

## Neutrality

This program does not add popularity bonuses, review-score bonuses, sponsorship ranking, vendor preference, house-product preference or identity-based weighting. Domain expertise defines the requirement taxonomy; evidence determines product capability status.
